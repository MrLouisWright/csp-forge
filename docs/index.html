csp-forge

Generate a tight Content-Security-Policy from your built site.

Point it at dist/, build/ or out/ (and optionally a live URL). It works out exactly which sources the site loads and writes a policy with sha256 hashes, or nonce + strict-dynamic for SSR, ready to paste into Nginx, Apache, Netlify, Vercel, Express/Helmet or a meta tag. --check fails CI when a deployed CSP is missing sources or too loose.

$ npm i -D csp-forge
Read the docs View on npm Source on GitHub

01 The problem

Writing a CSP by hand means guessing every script, style, font, image and API origin your site touches. Guess too tight and the site breaks; too loose and 'unsafe-inline' or * quietly defeats the point.

csp-forge reads your actual build output, hashes every inline block, and emits the narrowest policy that still works. Then --check keeps it honest in CI as the site changes.

02 Features

01

Built from your build

Scans HTML, CSS and JS in dist/ for scripts, styles, images, fonts, media, frames, workers, manifests and form actions.

02

Hashes or nonces

sha256 hashes for static sites, or nonce + strict-dynamic with SSR helpers and Express-style middleware.

03

Paste-ready formats

header, raw, meta, nginx, apache, netlify, vercel, express, helmet, json and reporting-endpoints.

04

--check for CI

Compare a policy string, file or live URL with what the build needs. Flags missing sources, unsafe keywords, wildcards and stale hashes.

05

Safe rollouts

--report-only with report-uri, or modern report-to + Reporting-Endpoints.

06

Vite & webpack plugins

Run the scan automatically after each production build.

07

--write

Inject the meta tag into every HTML file, or write dist/_headers for Netlify / Cloudflare Pages.

08

Zero runtime deps

Node ≥ 18, dual ESM/CJS, JSON and SARIF output.

03 Usage

# Generate a header

$ npx csp-forge dist -f header

# Write Netlify _headers

$ npx csp-forge dist -f netlify --write

# Nonce + strict-dynamic (SSR)

$ npx csp-forge dist --strict-dynamic -f header

# Check a live site against the build

$ npx csp-forge dist --check https://example.com

04 CI / GitHub Action

# .github/workflows/csp.yml
name: CSP
on: [push, pull_request]
permissions: { contents: read, security-events: write }
jobs:
  csp:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci && npm run build
      - run: npx csp-forge@1 dist --check dist/_headers --sarif csp.sarif
      - uses: github/codeql-action/upload-sarif@v3
        if: always()
        with: { sarif_file: csp.sarif }

05 Options & flags

FlagDescription
-u, --url <url>Also scan a live page (+ same-origin CSS/JS); its origin counts as 'self'
--origin <url>Treat this absolute origin as 'self' when scanning a directory
-c, --config <file>JSON config (default: .csp-forgerc.json / .cspbuilderrc.json / package.json "csp-forge")
-f, --format <fmt>header | raw | meta | nginx | apache | netlify | vercel | express | helmet | json | reporting-endpoints
--nonce[=value]'nonce-{{NONCE}}' (or 'nonce-<value>') instead of inline hashes
--strict-dynamicNonce mode with 'strict-dynamic' (best for SSR)
--report-onlyEmit Content-Security-Policy-Report-Only
--report-uri <url>Add report-uri (legacy reporting)
--report-to <name>Add report-to (use with --reporting-endpoint-url)
--reporting-endpoint-url <url>URL for the Reporting-Endpoints header
--frame-ancestors <v>Default 'none'; "off" omits it
--allow-wildcardsAllow collapsing 3+ subdomains into https://*.domain
--no-upgradeOmit upgrade-insecure-requests
--writemeta: inject <meta> into every HTML file; netlify: write <dir>/_headers
-q, --quietNo summary on stderr
--check <x>Policy string, file (HTML meta, _headers, nginx conf, vercel.json) or URL
--fail-on <level>error | warn | none (default: error)
--jsonPrint JSON results
--sarif [file]Print SARIF 2.1.0 (or write to file)
-t, --timeout <ms>Network timeout (default: 15000)
